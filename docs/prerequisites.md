# 前置条件：到底要准备哪些东西

由作者与 AI 共同整理。核对日期：2026-11-18。这里区分“原生 MCPX 能接通”的最小条件和作者自用增强桥的额外条件。

## 最小路线

| 要准备的东西 | 大白话解释 | 是否必需 |
| --- | --- | --- |
| 一台 Windows 电脑 | 文件和程序在这台电脑上运行；关机后网页不能继续访问它 | 是 |
| 可持续工作的网络 | 电脑要连到对外入口，网页平台也要能访问入口 | 是 |
| MCPX 的 Windows 版本 | 本机接收 MCP 请求、读取文件或执行获准操作的程序 | 是 |
| 可用的 HTTPS MCP 地址 | 例如 `https://mcp.example.com/mcp`，这是示例地址，不能照填 | 是 |
| 身份认证与授权 | 用来确认谁可访问，以及可以操作哪些目录和工具 | 是 |
| 网页账号的自定义连接器权限 | 有账号不等于有相应入口，能添加也不等于有写入或命令权限 | 是 |
| 演示目录 | 先准备 `C:/MCPX/demo` 和不含真实资料的 `marker.txt` | 首次验收必需 |
| 域名 | 采用稳定自建 HTTPS 入口时通常需要；具体取决于传输方案 | 取决于方案 |
| 隧道或等效远程传输 | 云端不能通过自己的 `localhost` 访问你的电脑 | 取决于网络架构 |

准确的下载来源、版本、配置和启动方法见 [Windows 安装](install-windows.md)。只采用本教程已核对的命令，不把作者电脑上的绝对路径直接粘贴到别人的电脑。

## 不必先装什么

直接使用原生 MCPX 工具读写文件、运行命令，不要求本机另有一个 Codex 模型来思考。网页 AI 已经负责生成操作要求。本机 Codex 仅在选择额外的模型委派路线时才成为依赖。

MCPX 发布的 Windows 程序和从源码构建是不同路线：使用发布程序不应被写成必须先搭建整套编译环境；源码构建按上游对应版本文档执行。

同样，不要把 Python、Git、自定义网关和 Cloudflare 某种专用代理适配一概写成所有 MCPX 用户的硬条件。它们是否必需，取决于使用的增强脚本、工作区隔离方式和传输方案。

## 作者自用增强桥额外做了什么

| 增强能力 | 为什么增加 | 安装原生 MCPX 是否自动得到 |
| --- | --- | --- |
| `windows_*` 工具目录 | 为网页 AI 提供统一手册、文件和任务入口 | 否 |
| 独立执行会话和工作区校验 | 不同聊天分别持有上下文和操作范围 | 否 |
| Git worktree 隔离 | 合适的 Git 项目可以在独立工作树修改 | 否 |
| 文件哈希冲突检查 | 修改前发现文件已被其他会话更新 | 需核对实际工具契约 |
| 独立命令 worker 和任务状态 | HTTP 断开后仍能查询被接纳的任务 | 需核对对应实现 |
| 监督、日志和恢复脚本 | 检查服务是否存活、是否就绪 | 否 |
| 可选 Codex 模型任务入口 | 在明确需要时调用本机模型完成任务 | 否；会涉及该路线的模型用量 |

作者当前部署的增强源码和配置不能直接整目录公开。本教程以原生最小路线为入门，扩展能力按单独说明和工具 schema 使用。

## 电脑需要保持什么状态

- 文件和命令路线要求电脑开机、服务运行、网络可用；睡眠和关机一般会使连接中断。
- 登录后自动启动与真正的系统开机服务是不同机制。采用哪种启动方式，要按安装步骤和当前用户权限确认，不承诺未登录时一定可用。
- 结构化文件与命令工具不等于桌面鼠标控制。需要操作浏览器或真实桌面时，还要对应插件、用户会话与资源协调。
- 多个聊天不能因为各自有连接器就同时抢同一窗口。文件修改要检查冲突，真实桌面操作需要串行协调。

## 手机端是什么角色

手机网页若支持相同连接器入口和工具权限，可以作为发起任务的一端；文件仍在那台 Windows 电脑执行。手机是否显示入口、是否支持当前工具、是否能完成授权，需要按产品当前版本实测，不能由电脑网页成功直接推断。

## 账号和额度核对

分别核对“允许添加自定义连接器”“允许工具写入/执行”“网页模型剩余用量”三件事。Claude 和 ChatGPT 的官方限制及本次覆盖范围见 [Claude](claude.md)与 [ChatGPT](chatgpt.md)。

不启动本机模型是执行路线的事实；网页对话免费、无限量或未来永远不变，不是这个事实的推论。
