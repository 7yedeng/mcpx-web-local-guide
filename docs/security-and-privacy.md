# 安全与隐私

这套连接可以把网页里的请求变成电脑上的实际操作。按需要授权，并保留现有的会话、目录和资源校验。

## 首次只开放演示目录

先用 `C:/MCPX/demo`，其中只放可公开的演示文本。不要把用户主目录、浏览器资料、密码库、密钥目录或真实业务数据作为首次验收对象。

真实项目需要单独确定目录、任务和允许动作。若使用全用户权限的命令执行器，仅依靠“工作目录在 demo”不能形成系统级隔离；程序本身仍可能访问当前用户可访问的其他位置。需要实际限制时，应采用执行器支持的工作区、命令或操作系统隔离机制。

## 保留认证和会话校验

- 对外地址使用有效 HTTPS，并完成对应身份认证与授权。
- 不通过关闭证书验证、公开未授权 Shell 或去掉 session 参数来处理连接失败。
- 每个入口只使用其自身返回的会话标识。原生的 `remote_session_id` 与增强工具的 `session_id` 不可互换。
- 不同账号、授权连接和聊天之间不能复制会话标识以扩大访问范围。
- 网络连接恢复后先查询已接纳任务，结果不明时不重复执行有副作用的命令。

## 文件修改与并发

修改前读取最新内容和版本。工具支持预期哈希时，写入须携带最新哈希；冲突时重新读取、合并，不强制覆盖。多个会话共用同一真实文件系统时，会话独立不代表文件自动隔离。

浏览器专用标签页与资源锁可以减少争用；真实 Windows 前台、鼠标和键盘操作需要排队。原生 MCPX 文件/命令接入本身不等于已有可用的浏览器或桌面控制插件。

## 不应公开的内容

不要提交令牌、OAuth 密钥、授权数据库、浏览器 Cookie、完整配置、真实日志、原始截图或账户邮箱。配置只保留占位符，示例地址使用 `mcp.example.com`。

截图采用不透明遮挡，必要时裁掉侧栏。脱敏后仍需逐张检查：头像、姓名、邮箱、账号菜单、地址栏、域名、目录、会话和任务标识、聊天标题、书签以及可识别业务内容都可能暴露信息。裁掉侧栏不应被描述成在网页里实际折叠了侧栏。

## 发布与撤销

v0.1.0 公开范围为教程、配置示例、提示词和已脱敏图片。后续发布前仍应检查每个改动文件和每张新增图片；本地忽略规则不能替代内容复核。

停止本机服务只影响后续连接，不会自动回滚已经写入的文件、已完成命令或部署。需要长期停用时，同时按对应产品撤销连接授权，并按服务的停用流程处理凭据。不要在教程中展示真实凭据或要求读者把凭据粘贴到聊天。
