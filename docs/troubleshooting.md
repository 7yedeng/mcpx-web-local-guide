# 常见问题与排查

先判断坏在哪一层，再做对应处理。避免把一个标签页报错、某次超时或一条关闭日志当成整个系统已失效。

| 表现 | 先核对 | 处理方向 |
| --- | --- | --- |
| 网页没有自定义连接器入口 | 套餐、地区、工作区策略与当前网页版本 | 对照平台官方说明；不要把其他账号的截图当成自己的权限 |
| 能添加，但写入或命令工具不可用 | 该账号和连接器允许的操作类型、实际 `tools/list` | 不通过改工具名称绕过产品权限 |
| 网页访问不到 `localhost` | 云端访问的是自己的网络环境 | 使用已授权、网页可达的 HTTPS MCP 入口 |
| 本机服务正常，公网入口超时 | 网络、远程传输、授权服务器可达性 | 分别检查本机、隧道和真实工具调用，不反复重装 MCPX |
| 授权页打不开 | 浏览器是否能访问 OAuth 授权地址 | 只迁移 MCP 传输不一定解决授权页可达性 |
| 手册变新，聊天仍只有旧工具 | 网页缓存的工具目录与实际 schema 是否一致 | 先按产品支持的刷新方式更新，必要时新开聊天重新选择连接器 |
| 会话不存在或权限拒绝 | 工具入口、授权身份、会话归属、目录范围 | 使用当前入口新建或读取自己的会话，不复制别人的 ID |
| 文件写入冲突 | 文件是否被另一会话修改 | 重新读取最新内容和哈希，再合并修改 |
| 长任务看起来断开 | 是否已返回任务 ID，任务状态是否仍在运行 | 查原任务状态，不把同一部署重新提交一次 |
| 本机 Codex 额度不足 | 是否误走模型委派路线 | 可用时改为直接工具路线；网页自身用量仍受限制 |
| 服务存在但一直未就绪 | 进程存活与端到端可用是否混淆 | 记录就绪状态与网络错误；身份不明时不要误杀或重复启动 |
| 浏览器或桌面操作互相干扰 | 是否争用同一标签页、应用或前台 | 分配专用标签页；桌面操作串行执行 |

## 最小诊断顺序

1. 电脑是否开机、未睡眠，目标服务是否仍在运行。
2. 本机服务是否能响应，与隧道是否就绪分别判断。
3. 外部 HTTPS 入口和 OAuth 授权页是否都可达。
4. 实际工具清单中是否包含所需工具，输入 schema 是否匹配。
5. 当前授权是否可以访问当前会话和演示目录。
6. 用无敏感内容的 marker 文件做真实读取，再核对本地结果。

每一步保留必要错误类型、时间和结果即可。公开求助时删去令牌、邮箱、自用域名、会话标识和真实业务日志；不要上传整个运行目录。

## 不能由这些结果推断什么

- `/ready` 成功不代表所有地区的网页服务都能访问。
- 一次工具读取成功不代表写入、命令、长任务或所有客户端已验证。
- 当前模型任务数没有增加不代表网页没有消耗自己的对话用量。
- 断网后能查到任务，不代表部署结果不明时可以安全重做。
- 截图中的按钮存在，不代表每个套餐和账号都具有同样权限。
